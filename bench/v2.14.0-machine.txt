Where the rows come from:
The five rows are the scaling entry at 32000 atoms and the cage block in
the reference run manifest of dseams2_repro, where the workflow/Snakefile
rules tip_scaling and tip_cages produce them. The v2.14.0 sources are
tests/bench_scaling.cpp and tests/bench_cages.cpp.

At N=32000 the neighbour list row times nneigh::neighListO, the ring
index row nneigh::getNewNeighbourListByIndex, and the CHILL+ row
chill::getCorrelPlus on the neighListO result. All three use the synthetic cubic cloud in bench_scaling.cpp: number
density 0.0332 atoms per cubic Å, cutoff 3.5 Å, atom type 1 and a
deterministic jitter. The manifest keys are neighListO_ms, byIndex_ms
and getCorrelPlus_ms.

At N=4096 the six-rings row times primitive::ringNetwork and the findHC
row times ring::findHC on the six-membered rings. Both use tests/bench_cages.cpp on input/traj/mW_cubic.lammpstrj, frame 1,
atom type 1, cutoff 3.5 Å. Every process reported 4096 atoms,
8192 rings and 8192 six-rings. N is the atom count. The manifest keys
are cages ringNetwork/ms and findHC/ms.

This run did not time the ring network of the 32000-atom cloud, and no
row shows it. The manifest leaves ringNetwork_ms empty at 16000 and 32000.

Driver change:
In the release, bench_scaling has no repeat argument and prints the
minimum of an internal loop. This run timed bench_scaling built with
v2.14.0-bench_scaling.patch applied. It calls each of the three functions
seven times and prints every call. Repeat 0 is the warm-up.
bench_cages is the released binary, run seven times with its repeat
argument set to 1. The first process is the warm-up. Its printer rounds
those two stages to 0.001 ms, and the csv keeps that printed value.

Commands, from the input directory of the v2.14.0 build tree, with the
environment above:
taskset -c 0 ../build-rel/tests/bench_scaling 32000
taskset -c 0 ../build-rel/tests/bench_cages traj/mW_cubic.lammpstrj 1 1

No row is a threaded sweep. OpenMP is linked and limited to one thread.
